# RMPC Assignment2 项目说明与三种路径规划算法解析

## 1. 项目整体目标
这个项目是机器人运动规划与控制课程作业，核心目标是：

- 在二维栅格地图中为机器人生成一条从起点到终点的可行路径；
- 路径需要避开障碍物；
- 将离散路径进一步转成可执行的轨迹（含速度、加速度、角速度等时序信息）；
- 可视化不同路径规划方法的结果（Lattice / RRT / PRM）并进行对比。

通俗理解：
> 先“找路”（Path Planning），再“把路变成车能跟踪的运动曲线”（Trajectory Generation）。

## 2. 项目结构与各模块作用

```text
RMPC_Assignment2/
├── README.md
└── PathPlanner/
    ├── main.py
    ├── path_planner/
    │   ├── lattice_planner.py
    │   ├── rrt_planner.py
    │   ├── prm_planner.py
    │   └── utils.py
    └── trajectory_generator/
        └── traj_generation.py
```

### `PathPlanner/main.py`
主程序入口，负责：

1. 构建地图尺寸和障碍物；
2. 设置起点终点；
3. 分别调用三种规划器：
   - Lattice（内部用 A*）
   - RRT
   - PRM
4. 对 Lattice 路径做插值与轨迹重采样；
5. 输出路径长度与碰撞检测诊断信息；
6. 绘图展示三条路径和速度-时间曲线。

### `path_planner/utils.py`
底层基础模块，主要提供：

- 图结构 `Graph`（顶点、边、邻接矩阵）；
- 障碍物网格 `ObstaclesGrid`；
- 点碰撞、线段碰撞、边可行性检查等通用函数。

这是“碰撞检测与地图约束”的核心。

### `path_planner/lattice_planner.py`
Lattice 图规划器：

- 把状态定义为 `(row, col, heading)`；
- 用预定义运动原语（直行 / 转弯弧线）构建有向图；
- 对不可通行边赋无穷代价；
- 使用 A* 在图中搜索到达目标状态的最优路径（相对该离散图与代价定义）。

### `path_planner/rrt_planner.py`
RRT（Rapidly-exploring Random Tree）采样树方法：

- 从起点不断随机采样、扩展树；
- 每次朝随机点走一小步；
- 使用线段碰撞检测保证新边安全；
- 到达目标后回溯得到路径；
- 再做 shortcut 平滑（在保证不碰撞的前提下删掉冗余拐点）缩短路径。

### `path_planner/prm_planner.py`
PRM（Probabilistic Roadmap）概率路网方法：

- 先在自由空间随机采样节点；
- 把每个点和其若干近邻连边（连线必须无碰撞）；
- 在路网上执行图搜索（A*风格）；
- 找到起终点连通路径后同样做 shortcut 优化。

### `trajectory_generator/traj_generation.py`
轨迹生成器，把路径转成随时间变化的状态序列：

- 插值空间点与朝向；
- 根据距离生成时间分配；
- 计算速度、角速度、加速度；
- 输出可用于控制器跟踪的轨迹状态列表。

## 3. 三种算法详细说明

> 这里的“三种算法”对应本项目中三条路径：Lattice(A*)、RRT、PRM。

## 3.1 Lattice + A*

### 核心思想
先把机器人可行动作离散化成“运动原语”（直行、左/右转弧），再在状态图中搜索。

状态不仅包含位置，还包含朝向，因此能体现“车体运动学约束”。

### 主要流程
1. 生成离散状态节点 `(row, col, angle)`；
2. 根据运动原语连接边并赋代价（直线、弧线代价不同）；
3. 用障碍物检测筛掉非法边（代价设为 `inf`）；
4. A* 搜索最小代价路径；
5. 对路径插值以获得更细轨迹点。

### 优点
- 结果更符合车辆运动约束，路径平滑性通常较好；
- A* 在固定图上有较强可解释性。

### 局限
- 最优性仅在“当前离散图 + 代价定义”下成立；
- 分辨率和原语质量决定结果上限；
- 图过密时计算开销上升。

---

## 3.2 RRT

### 核心思想
在连续空间中随机扩展一棵树，快速探索高维/复杂自由空间。

### 主要流程
1. 随机采样一个点（带少量目标偏置）；
2. 找树中离采样点最近的节点；
3. 从最近节点朝采样点推进 `step_size` 生成新节点；
4. 若新边无碰撞则加入树；
5. 若接近目标则回溯路径；
6. 对路径进行 shortcut 压缩，删掉可被“直连且无碰撞”替代的中间段。

### 优点
- 实现相对简单；
- 在复杂障碍中常能较快找到可行解。

### 局限
- 原生 RRT 偏“可行”而非“最优”；
- 路径常有锯齿与绕路，需要后处理；
- 结果受随机种子影响。

---

## 3.3 PRM

### 核心思想
先构建“自由空间路网”，再在图上做搜索。

### 主要流程
1. 采样大量无碰撞节点；
2. 每个节点连接 `k` 个近邻（连边需无碰撞）；
3. 得到概率路网；
4. 通过图搜索求起点到终点路径；
5. 对路径执行 shortcut 优化。

### 优点
- 对多次查询（同地图多起终点）很有价值：路网可复用；
- 在空旷区域可得到较好可行路径。

### 局限
- 路网质量依赖采样密度与连边策略；
- 狭窄通道容易采样不足；
- 不是严格全局最短算法。

---

## 4. 障碍物规避是如何保证的
本项目避障并非仅“看节点”，而是对**线段**做连续检查：

- `is_point_collision`：检查点是否碰撞（支持 `clearance` 安全距离）；
- `is_segment_collision`：沿线段按步长采样，逐点检测；
- RRT / PRM 连边前都要过线段碰撞检测；
- shortcut 只有在“新直连线段无碰撞”时才会接受。

因此，路径优化不会以穿越障碍为代价。

---

## 5. 结果如何解读（你最关心的“是不是最短”）

- **Lattice**：在离散动作图上通常是“代价最优”，但不等于连续空间绝对最短；
- **RRT / PRM**：随机采样方法一般不保证全局最短；
- 项目中的改进（更密采样 + shortcut）会显著减少绕路，但仍应理解为“更短、可行、工程可用”，不是数学意义绝对最短。

如果你需要“严格最短”定义，可考虑：
- 在网格上用 Dijkstra/A*（无运动学约束版本）；或
- 采用 RRT* / PRM* 这类渐近最优算法。

## 6. 项目当前实现的价值

该项目已经完整覆盖了移动机器人路径与轨迹生成的一条典型工程链路：

1. 地图与障碍建模；
2. 多算法路径规划（Lattice、RRT、PRM）并行对比；
3. 路径可行性（碰撞）验证；
4. 轨迹时间化（速度/加速度/角速度）；
5. 可视化分析与算法调参。

这使它不仅是“能跑通作业”的代码，也具备进一步扩展到：
- 动态障碍；
- 实车速度约束；
- 控制器闭环跟踪评估；
- 最优性与计算时间对比实验。

## 7. 快速运行
在仓库中执行：

```bash
cd PathPlanner
python3 main.py
```

运行后会看到：
- 地图与三条路径对比图；
- Lattice 速度-时间曲线；
- 终端中的路径诊断信息（长度、是否碰撞）。
